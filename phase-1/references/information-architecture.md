# Information architecture rules

Start from actor goals and use cases, then define hierarchy and grouping. Prefer labels that reflect the user’s task, group related content and actions, distinguish global from local navigation, and show only the information needed for the current decision. Make locations and next actions discoverable; record terminology once for large systems.

Do not create categories because of implementation boundaries, put unrelated goals in one location, or conceal required steps behind an unexplained label. Treat IA changes as structural changes subject to the lock.
