# Visual craft review

Review a rendered representative route against the active grammar.

| Lens | Ask | Evidence |
|---|---|---|
| hierarchy | Can a user identify task, primary action and group order immediately? | route/viewport/capture |
| character | Do color, type, surfaces and motion express the stated product direction? | grammar decision |
| components | Are equivalent controls visibly and behaviorally equivalent? | component/state sample |
| restraint | Does every border, card, icon, shadow, badge and animation have a job? | removal/keep rationale |
| preservation | Were coherent existing patterns retained unless a documented reason justified change? | classification record |
| direction | Does the design have a recognizable visual direction traceable to the selected archetype/DNA? | `DESIGN-INSPIRATION.md` / direction |
| typography | Does typography support the intended character (hierarchy, measure, pairing, language coverage)? | [typography-review](../typography/typography-review.md) codes |
| composition | Does the composition fit the product and content, or does the page read as a default landing template? | pattern selection record; `GENERIC_TEMPLATE_COMPOSITION` |
| narrative | Do sections create narrative rhythm (claims followed by evidence, density varied by job)? | `VISUAL_STORYTELLING_WEAK` check |
| motion purpose | Does each motion have a purpose, and is intensity controlled within the budget with reduced-motion equivalents? | [motion-review](../motion/motion-review.md) codes |
| references | Are reference influences transformed rather than copied (distance test)? | [anti-copying](../design-inspiration/anti-copying.md) |
| memorability | Is the experience memorable without becoming decorative noise? | one signature moment identified; AI-tell density |
| premium quality | Do hierarchy, consistency, feedback, continuity, detail, responsiveness, performance, accessibility and restraint hold together? | [premium quality model](../knowledge/composition/premium-quality-model.md); E65–E80 |
| homogenization | Does the page fall back on the default tech look without reasons? | [anti-homogenization](../knowledge/composition/anti-homogenization.md); `HOMOGENIZED_DESIGN` |

Log each defect with grammar rule, affected component, severity, proposed smallest fix and verification target in `VISUAL-REVIEW.md`.

Load the typography, motion, pattern and reference checks only for the dimensions the task changed; an already-good dimension is recorded as `KEEP`.
