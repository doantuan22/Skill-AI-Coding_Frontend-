# Visual grammar

Define a visible, explainable language before polishing components. Record intent, evidence and exceptions in `VISUAL-GRAMMAR.md`; never infer a new direction from a framework default.

- **Composition:** identify dominant task/action, reading order, density, grouping rhythm, and where deliberate asymmetry or restraint serves the product.
- **Color character:** choose neutral temperature, accent role/frequency, semantic intensity, surface contrast and dark-mode behavior; accents signal priority, not decoration.
- **Typography character:** state what the type voice communicates, hierarchy contrast, body readability, numeric/data treatment and exceptions. A popular font is neither automatically good nor bad.
- **Surface profile:** assign each boundary a job: space, divider, tonal region, bordered surface, or elevation. A card needs a grouping/elevation reason.
- **Motion character:** define which state changes get motion, timing family, spatial logic and reduced-motion equivalent. Motion must reveal feedback, state or orientation.
- **Component personality:** ensure controls share the same hierarchy, density, radius/elevation and feedback language without making all components visually identical.

Read [craft-foundations.md](craft-foundations.md) for checks and [ai-tell-density.md](ai-tell-density.md) for cluster analysis.
