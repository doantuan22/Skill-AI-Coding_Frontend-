# Typographic composition

Reusable arrangements of type that create hierarchy without extra containers. Choose by content and archetype.

| Pattern | Anatomy | Use when | Avoid when |
|---|---|---|---|
| **Oversized display** | 1–6 words at display max, minimal support | One declarative message; premium/portfolio/launch | Message needs explanation; dense products; every section |
| **Editorial headline** | Serif or characterful headline, deck/standfirst, byline/meta | Editorial and knowledge products; chapter openers | Transactional UI |
| **Compact product title** | h1 at modest size + key facts inline | Product detail, app pages, developer docs | Brand storytelling moments |
| **Eyebrow + headline + support** | Small label (category/step) → headline → 1–2 sentence support | Sections needing context; the eyebrow must carry information | The eyebrow is decorative ("Features") on every section — then drop it |
| **Metric typography** | Large tabular number + unit + label + source | Real, meaningful metrics; proof sections | Invented or vanity numbers; more than 3–4 metrics in a row |
| **Mono metadata** | Mono small text for version/date/ID/status | Developer/technical archetypes | Non-technical products |
| **Balanced reading width** | Text column constrained to measure, media may break out | Articles, docs, long explanations | — (always for reading) |
| **Pull quote / testimonial type** | Quote at h3–h2 scale, attribution small | Real quotes with attribution | Anonymous or fabricated quotes |
| **Split headline** | Headline left, support/CTA right on desktop, stacked on mobile | Editorial or premium sections with short copy | When support text is long |

Rules:

- A page uses 3–5 of these, not all. Repeating eyebrow+headline+support for every section is a template tell.
- Every eyebrow, metric and quote must carry real information.
- Typography should do the grouping work that cards would otherwise do, especially in editorial/premium archetypes.
