# Component contract rules

For each shared component, specify purpose, variants, sizes, content rules, interaction, default/hover/focus/active/loading/disabled/error/success states as relevant, accessibility behavior, responsive behavior, and visual tokens used. A button may have primary/secondary/ghost/destructive variants and small/medium/large sizes only if the product needs them.

Do not create parallel components with the same role (`Button2`, `NewButton`, etc.). Preserve the structural inputs/outputs from Phase 1 and use semantic HTML where appropriate.
