# State model

Create `STATE-MAP.md` for important screens, data regions, and interactions. Consider default, loading, empty, error, success, disabled, partial, permission-denied, cancellation, and no-match states where applicable. Map each state to its trigger, user-visible purpose, permitted actions, recovery path, and affected page or component.

State coverage belongs to structural completeness. Do not invent backend behavior; state transitions must follow confirmed rules or be marked as assumptions/questions.
