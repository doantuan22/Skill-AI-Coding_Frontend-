# Page architecture

Create `PAGE-MAP.md` and `PAGE-SPEC.md` from flows and IA. Every page needs an ID, name, actor, purpose, related use cases, entry and exit points, primary and secondary actions, required data, related pages, sections, navigation, states, and business constraints.

Give each page one clear responsibility. If it mixes unrelated goals, unrelated actions, or excessive information, split it, reorganize its sections, or use progressive disclosure. Classify content as critical, primary, secondary, supporting, or optional. The coarse layout order is header → primary context → main content → secondary content → actions → feedback/states; it is structural, not visual styling.
