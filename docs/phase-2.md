# Phase 2 operation

Phase 2 starts only with an active Structure Lock and its referenced Phase 1 artifacts. It loads `SKILL.md`, `phase-2/README.md`, and `phase-2/router.md`; the router records task mode, project/page type, stack, existing-system state, lock version, selected artifacts/references, viewport targets, assumptions, and blockers. Missing or invalid input blocks the work. A semantic mismatch creates a rollback request to Phase 1 rather than a Phase 2 lock edit.

The workflow is lock → frontend analysis → Design Direction → Design Intelligence → Design System/Tokens → components → implementation → responsive/interactions/states → rendered QA → accessibility → final quality gate. References load by need: form work does not require dashboard guidance, and a simple polish does not require a migration plan.

`DESIGN-DIRECTION.md` turns the locked Design Brief into task-appropriate visual intent. `DESIGN-SYSTEM.md` and `DESIGN-TOKENS.md` become the implementation source of truth mapped to the existing stack. `COMPONENT-SPEC.md` and `IMPLEMENTATION-MAP.md` link structural components and Page IDs to realized components, source paths, and style sources.

The visual QA loop requires a running/rendered application and selected desktop/mobile inspection; compilation alone is not success. When executable capability exists, visual QA requires runtime evidence from an execution session/manifest before finalization. It has at most three automatic refinements, then blocks unresolved blockers. The final quality gate checks Structure Lock/Page Spec compliance, system/token drift, states, responsive behavior, visual QA, accessibility, consistency, and applicable performance evidence. A passing gate proceeds to final review; an implementation issue returns to Phase 2 and a structural issue to Phase 1.

Between direction and tokens, the router may select the [Design Inspiration Engine](../phase-2/design-inspiration/README.md) (archetype, reference DNA, pattern candidates → `DESIGN-INSPIRATION.md`) and [Typography Intelligence](../phase-2/typography/README.md) (type character → Typography system in `DESIGN-SYSTEM.md`). After Visual Grammar, the [Motion Engine](../phase-2/motion/README.md) defines temporal behavior (`MOTION-SYSTEM.md` for medium/high budgets) and the [Web Pattern Library](../phase-2/web-patterns/README.md) supplies composition options selected from content. All four load by task trigger; a dashboard never loads cinematic landing patterns, and a small form loads only typography role files and microinteractions.
